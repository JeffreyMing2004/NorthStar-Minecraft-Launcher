# 模组与整合包

目前接入 Modrinth 公共 API，无需为搜索与下载填写 API Key。启动器界面及安装逻辑均为 Rust，沿用原有的后台任务、进度和取消入口。

模组与整合包搜索列表显示项目 Logo，版本页和安装确认页沿用所选项目的图标。图片在后台加载，最多并发 4 个请求，并在设置文件旁的 `cache/project-icons/` 缓存缩略图；翻页或再次打开启动器时可复用。支持 PNG、JPEG、WebP 和 GIF 首帧，保持原始比例及透明背景。没有 Logo、图片损坏或网络失败时显示项目名称首字占位，不影响搜索、下载与安装。

## 模组下载

1. 在「下载 → Minecraft」安装游戏和 Forge、Fabric 或 NeoForge。
2. 打开「下载 → Mod」，选择目标实例。原版实例不能直接安装这些加载器的模组。
3. 输入关键词后搜索，留空可浏览资源；支持翻页。搜索及发布版本列表按实例的游戏版本、加载器筛选，收到版本信息后还会再次检查，避免只依赖搜索索引。
4. 点击项目的「查看版本」，再点击「查看方案」。启动器读取指定发布版本，递归解析必需依赖，并检查与已登记模组的版本要求和冲突声明。
5. 确认方案中的模组与依赖，再点击「安装模组及依赖」。下载并校验全部文件后才修改实例的 `mods/` 目录。
6. 回到开始页选择该实例启动。也可在 Mod 页点击「检查兼容性」，查看已登记文件的完整性、游戏版本、加载器与依赖检查结果。

必需依赖会自动安装，可选依赖不会自动安装。固定版本依赖必须匹配；同一项目要求不同版本、缺少兼容版本、不可解析的必需文件、声明不兼容的项目或仅支持服务端的资源会阻止安装。依赖解析最多处理 256 个项目，不会强行绕过冲突安装。

更新已登记的同一项目时会替换旧 JAR，其他模组、配置和存档保留。未登记的同名不同内容文件、手动修改过的已登记 JAR 不会被覆盖，会提示先移出该文件后重试。更改实例游戏版本、归档或移除实例后需重新生成安装方案。

## 整合包下载与导入

1. 打开「下载 → 整合包」，搜索 Modrinth 并选择发布版本；也可填写本地 `.mrpack` 路径后点击「导入整合包」，或把文件拖入此页。
2. 检查安装方案中要求的 Minecraft、加载器和文件数量。有可选客户端文件时，通过复选框选择是否包含，默认不包含。
3. 点击「安装整合包」。启动器校验并暂存资源，安装清单指定的游戏及加载器精确版本，再创建新的独立实例。
4. 完成后在开始页选择新实例。即使再次安装相同整合包，也会创建新实例，不会覆盖已有包的存档。

支持 Modrinth v1 格式，识别 `minecraft`、`forge`、`fabric-loader`、`neoforge` 依赖。未知组件、Quilt、多个加载器或没有游戏版本的包会给出明确错误。仅安装适用于客户端的文件，跳过 `client: unsupported` 和 `server-overrides/`；按用户选择处理 `client: optional`。公共 `overrides/` 先应用，`client-overrides/` 后应用。

## 校验与失败恢复

- 下载文件同时检查 SHA-1、SHA-512 与文件长度，整合包最多并发下载 4 个文件，支持清单中的备用下载地址。资源下载地址限于 Modrinth CDN、GitHub、GitLab 的 HTTPS 地址；Minecraft 和加载器依赖继续使用设置中选择的游戏下载源。
- 下载缓存在游戏文件目录的 `.nscl/content-cache/`，安装时在 `.nscl/content-work/` 暂存。模组替换前备份旧文件，取消或文件发布失败时恢复本次替换；恢复失败时保留备份并显示位置。
- 整合包文件与实例配置全部准备成功后，才移入 `instances/<独立实例 ID>/`。取消、错误校验值或下载失败不会发布半完成的整合包实例；已下载的有效缓存和共享游戏依赖可复用。
- 拒绝目录穿越、绝对路径、Windows 设备名和文件流、符号链接、重复及大小写冲突路径，也拒绝覆盖启动器的实例配置或安装记录。单文件上限 512 MiB，整合包内容上限 4 GiB，最多 10000 个下载项和 20000 个压缩条目。
- 实例中的 `.nscl-content.json` 保存 Modrinth 发布信息、依赖与文件校验记录，不保存账号令牌。检查会区分损坏的模组 JAR、玩家修改过的整合包配置，以及未单独登记的 JAR。

## 兼容性检查的范围

检查以 Modrinth 发布信息和整合包清单为依据，包括 Minecraft 版本、加载器种类、固定或项目依赖、冲突声明、客户端支持状态及已登记文件的完整性。Forge 与 NeoForge、Fabric 与 Quilt 不会被当作同一种加载器。

整合包自带 JAR 依据包声明的组件和文件校验值检查；手动加入的 JAR 会提示缺少独立依赖记录。目前不完整解析任意 JAR 内的运行时版本约束，也不保证任意第三方模组之间没有运行时冲突。错误可通过启动日志继续排查。

当前不支持 CurseForge API / manifest 整合包、Quilt、模组自动更新或卸载。不能把普通 ZIP 或 CurseForge 包改名为 `.mrpack` 导入。

- [官方 `.mrpack` 格式](https://support.modrinth.com/en/articles/8802351-modrinth-modpack-format-mrpack)

自动测试使用本地模拟服务覆盖依赖安装、模组更新保留存档、游戏版本及加载器不匹配、仅服务端资源、冲突依赖、下载取消、错误校验值、同名文件保护、写入失败回退、客户端覆盖文件和独立实例创建。桌面交互测试覆盖最小窗口布局和整合包确认前不安装。

Logo 测试覆盖常见图片格式、透明背景、等比例绘制、请求去重、重启后缓存复用、损坏缓存恢复和缺图回退。已通过 Sodium 模组与 Fabulously Optimized 整合包的真实 Logo 下载验证；需要联网复测时运行 `cargo test --bin nscl live_modrinth_mod_and_modpack_logos -- --ignored --nocapture`。

已在独立 Windows 测试实例中通过真实 Modrinth API 下载并安装 Iris `1.7.6+1.20.1` 和其指定的 Sodium 依赖，完整性及依赖检查通过。Fabulously Optimized `5.2.8`（Minecraft `1.20.1` / Fabric `0.14.22`）也已完成真实下载、加载器安装与独立实例创建，校验 52 个下载文件和 27 个配置/附带文件。此验证覆盖下载与安装，不等同于所有模组组合的游戏运行验证。
