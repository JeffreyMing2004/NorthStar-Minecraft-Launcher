# NSCL UI 方案草案

状态：**已切换为纯 Rust 原生界面（eframe/egui）。** 已接入原版及 Forge / Fabric / NeoForge 安装与启动、Microsoft 正版登录、Java 配置、独立实例管理，以及 Modrinth 模组和整合包下载；皮肤预览仍为后续实现目标。真实账号授权需应用权限及用户本人操作，历史技术选型记录保留在下文。

## 技术方案

**当前采用 Rust + eframe/egui**：无 WebView、无 JavaScript，界面与业务逻辑全部为 Rust。中文字体运行时从系统目录加载；设置以 JSON 存于本机（调试构建在可执行文件旁，发布构建在 `%LOCALAPPDATA%\<identifier>`）。3D 皮肤预览计划用 egui + wgpu 自绘实现。

历史决策记录：最初在 Tauri 2 + Vue 3 与 egui 之间取舍，考虑到主题定制与皮肤展示先选了 Web UI，并约定「若确定界面必须纯 Rust 则重新评估 egui」。2026-10 依据该约定完成切换，理由是：项目对外定位为「Rust 编写的启动器」，当时前端 JavaScript 仅约 40 行、页面均为空状态，迁移成本处于最低点；且 egui 的表格/进度/表单组件适合下载列表等工具型界面，wgpu 自绘为 3D 皮肤预览提供成熟路径。

官方参考：[Tauri 进程模型](https://tauri.app/concept/process-model/)、[egui 项目说明](https://github.com/emilk/egui)。

## 顶部布局

- 左上角：`NorthStar Minecraft Launcher (v{version})`；空间不足时显示 `NSCL (v{version})`，悬停可查看全名。
- 中间：固定顺序 **开始 / 账号 / 下载 / 设置 / 更多**。
- 右上角：窗口最小化、最大化或还原、关闭按钮。
- 版本号来自应用版本信息，不在界面中写死；设计示例中的版本占位符不代表已发布版本。
- 导航相对整个窗口居中，左右区域预留等宽空间。先切换品牌简称，再在较窄窗口将导航移到独立第二行，避免文字与窗口按钮重叠。
- 当前页使用背景高亮及短下划线；支持键盘焦点，不能仅靠颜色区分。
- 顶栏空白区域可拖动窗口；导航、品牌链接及窗口控制按钮不属于拖动区域。

## 页面职责

| 导航 | 主要内容 |
| --- | --- |
| 开始 | 当前实例、版本选择、启动按钮、账号摘要、皮肤预览；实例管理入口放在版本选择旁 |
| 账号 | 「账号管理」与「皮肤与预览」两个标签，分别处理登录身份和皮肤操作 |
| 下载 | 二级分类：Minecraft、整合包、Mod；先选游戏版本再选加载器，Mod 浏览与下载不绑定实例，整合包支持搜索及本地导入 |
| 设置 | Java 路径与自动安装、内存、游戏目录、下载源与官方回退 |
| 更多 | 关于、更新日志、日志与诊断、项目仓库入口 |

「下载 → Minecraft」进入后自动加载并直接显示游戏版本，支持版本搜索与快照筛选。点击「选择版本」进入安装选项，默认不安装加载器，也可选择 Forge、Fabric 或 NeoForge 及兼容版本；最后统一点击「开始安装」或「校验 / 修复」。设置页可选择官方、BMCLAPI、mirror.minguncle.cn 或自定义兼容镜像；首页会展示已完成安装的版本。任务在后台运行，提供进度及取消入口；启动失败显示原因，并可查看游戏日志。具体操作见 [原版客户端安装与启动](vanilla-client.md)。

下载页使用独立滚动的版本列表，高度随窗口调整。版本行高 72px、行距 10px，版本号与发布日期分层排列；选择游戏版本后显示独立安装选项，保留返回入口，兼容加载器列表在中间滚动，底部固定显示安装摘要及确认按钮。加载器列表查询在列表内显示进度及取消入口，安装进度集中在底部。

账号页默认提供 Microsoft 浏览器 PKCE 授权、多账号选择与移除，密码与多因素验证在官方网页完成，设备代码作为备用方式。应用 Client ID 与登录回调 URI 在后台管理，设置页提供 Java 扫描与路径检测；首页的实例管理窗口支持创建、重命名、独立 Java/内存配置，以及保留存档的归档和恢复。操作说明见 [账号、Java 与实例管理](accounts-and-instances.md)。

首页右侧直接绘制当前角色的 3D 皮肤，底部提供「管理账号」与「更换皮肤」入口。皮肤标签在宽窗口使用模型与操作区并排布局，窄窗口纵向排列；支持拖动旋转、双击复位、本地 PNG 预览、标准/纤细手臂切换及正版上传。刷新与上传状态独立于游戏下载任务，账号切换后丢弃旧账号的迟到结果。

设置页在 Java 检测区提供主版本选择、按实例要求选择和「下载并安装」，安装过程中显示字节进度与可用的取消按钮。下载的 Java 自动加入运行时扫描范围，不修改系统 Java 配置。

“开始”是页面导航，“启动游戏”是页面内操作，避免点击导航就意外启动游戏。Forge、Fabric、NeoForge 在下载页按目标游戏版本选择并创建对应实例。

Mod 与整合包页采用“搜索 → 发布版本 → 安装方案 → 确认安装”的流程。Mod 页只浏览 Modrinth，按发布版本直接下载 JAR 到启动器下载目录，不绑定实例；整合包展示要求的组件、下载文件和可选客户端文件，安装为独立实例。列表独立滚动，兼容性检查在单独窗口显示错误和提示。操作说明见 [模组与整合包](mods-and-modpacks.md)。

实例的模组管理放在「版本管理 → 实例 → 模组」标签页：搜索按该实例的游戏版本及加载器筛选，方案中列出必需依赖及未登记文件的检查范围，更新与卸载方案也在同一标签页内确认，离开标签页不会把操作带到下载页。

版本管理还提供「资源包」「光影」标签页。三类本地资源使用同一列表交互，支持导入、搜索、启用/禁用和确认移除，移除文件保留到实例的本地回收目录。读取、复制与元数据解析在后台执行，列表使用共享快照和按需绘制。详见[实例资源管理](local-resources.md)。

## 首页状态与交互

- 无实例：显示“安装 Minecraft”，跳转下载页；不展示可点击的启动按钮。
- 未登录或登录失效：在账号区给出登录入口，并在需要认证时明确说明。
- 正常就绪：突出“启动游戏”，旁边展示当前实例和账号。
- 准备或启动中：展示具体阶段，防止重复点击；失败时提供重试和日志入口。
- 下载中：底部展示进度并可打开任务详情，切换页面不会丢失任务状态。
- 皮肤加载失败：显示默认模型或占位图及重试入口，不阻塞其他页面操作。
- 皮肤修改：本地预览与账号皮肤上传分开，只有服务确认成功后显示“修改成功”。

## 视觉建议

- 默认深色主题：深蓝灰背景、略亮的内容卡片、蓝青色强调色；后续增加浅色与跟随系统。
- 默认窗口建议 1200 × 760，最小尺寸建议 960 × 640，均为逻辑像素；高 DPI 下验证布局。
- 按 `image/` 参照图还原：顶栏 72 像素，内容左右边距 42 像素，卡片圆角 16 像素；导航按钮宽 64 像素，间隔 6 像素，整体相对窗口居中。
- 首页采用 1.85:1 的两栏比例，间隔 22 像素。较矮窗口压缩横幅高度，内容超过可用区域时滚动，避免遮住账号入口或底部状态栏。
- 按钮显式绘制主题背景、悬停和键盘焦点，避免 egui 默认灰色控件覆盖主题。天空与光晕使用顶点颜色插值，避免条纹和同心环。
- Java 路径和内存均使用有内边距的圆角输入框；内存输入保留 1024–32768 MiB 整数校验。
- 首页保持一个主要操作按钮；装饰与动画不影响文本可读性，支持减少动态效果。
- 皮肤预览仅在可见时持续渲染，隐藏页面暂停动画；首次实现时验证不同系统及图形后端的显示效果。

调试构建可以显式设置 `NSCL_SCREENSHOT` 为 BMP 文件路径，在启动时导出一张应用画面；`NSCL_PREVIEW_PAGE` 可设为五个导航页的中文名称。未设置时正常从首页启动，不自动保存截图；发布构建不包含这些调试入口。截图应写入 `target/` 等本地忽略目录。

## 首版验收

- 五个导航入口可切换，选中状态与页面内容一致。
- 完整名称和简称切换时不遮挡居中导航或窗口按钮。
- 最小窗口、高 DPI、长玩家名称与长实例名称下没有重叠或不可访问的操作。
- 键盘可以访问导航及主要操作，焦点清晰可见。
- 空状态、加载中、失败、就绪等状态可区分，原型数据不能被描述为已完成的真实功能。
- 皮肤预览、账号认证与下载后端分别验证后再接入主界面。
