# 启动器功能完善建议

评估日期：2026-11-01。代码基线：`b0a5432`。对照对象：PCL、HMCL、Prism Launcher、Modrinth App 的官方资料。

本报告基于本仓库代码和文档的静态审阅，以及可访问的竞品官方资料，不代表各启动器的完整功能测试。“未发现”表示当前审阅范围内没有发现对应实现或入口；优先级是针对 NSCL 当前阶段的产品建议，并非已确认的故障等级。工作量为相对估计，不是工期承诺。

## 结论

NSCL 已覆盖安装、登录、Java、实例隔离、模组依赖、整合包导入导出和联机等核心能力。下一阶段建议优先完善玩家长期使用时的恢复能力、进程控制和内容维护，然后扩展下载生态。

建议最先完成三件事：**实例备份与克隆、游戏停止与实时日志、整合包版本升级与回退**。CurseForge 是值得补齐的生态入口，但 API 接入和受限文件处理需要单独设计，可在上述基础能力建设时开展接入验证。

## P0：先改善恢复和排障

### 1. 实例备份、存档恢复点与克隆

**现状：**归档会移动实例目录；共享或沿用版本目录的数据仍留在原目录。导出 `.mrpack` 可选择包含存档，但不等同于保留可随时恢复的实例快照。当前未发现独立的备份计划、恢复点列表或实例克隆入口。[依据](../src/instances.rs#L238)

**建议：**增加“备份实例”“备份存档”“从备份恢复”“复制为新实例”。在整合包升级、批量模组变更前提供恢复点；备份保存到独立位置，显示时间、大小和保留数量。克隆时可选择是否复制存档、截图和服务器列表。

**最小验收：**游戏关闭后创建备份，修改测试实例，再恢复至备份状态；源实例与克隆实例互不影响；共享目录明确提示实际备份范围；失败不覆盖原数据。初期只允许游戏退出后备份。工作量：中；是整合包升级与历史回退的基础。

### 2. 游戏停止、实时日志和本次启动诊断

**现状：**启动线程持有子进程并调用 `child.wait()`；服务只记录一个运行游戏的 PID 和日志路径，未发现游戏停止入口。日志窗口加载的是一次性报告，诊断读取启动日志及 `latest.log` 末尾，文档明确后者可能来自上次运行。已有常见错误识别和脱敏诊断包。[进程依据](../src/minecraft/launch.rs#L241)、[服务状态](../src/service.rs#L55)、[日志依据](../src/diagnostics.rs#L89)

**建议：**运行时增加“停止游戏”和确认后的“强制结束”；日志窗口自动追踪、搜索、按级别过滤、暂停滚动。为每次启动记录独立会话，异常退出时关联此次生成的 `crash-reports`、`hs_err_pid` 和加载器日志；诊断结果给出证据及可执行建议。

**最小验收：**卡住的测试子进程可结束，界面恢复到可启动状态；不能误结束其他 Java 进程；新日志持续出现；旧日志不会被当成本次崩溃证据；诊断导出保持现有敏感信息保护。工作量：中。

## 建议实施批次

1. **恢复与排障：**实例备份/恢复/克隆，游戏停止，按启动会话查看日志与诊断；同时验证 CurseForge 接入条件。
2. **内容维护：**整合包升级与回退，CurseForge 包导入，手动模组来源识别与批量更新预览。
3. **日常体验：**下载任务中心及续传，高级启动参数，资源包/光影在线管理，缺少 Java 的任务内引导。
4. **联机和生态：**可选端口、环境差异检查，按目标用户需求补充 Quilt、外置认证和实例组织能力。

建议以完整用户场景验收：**新电脑首次运行 → 登录并安装整合包 → 加入好友 → 更新整合包 → 遇到失败 → 查看原因并恢复可玩状态**。
