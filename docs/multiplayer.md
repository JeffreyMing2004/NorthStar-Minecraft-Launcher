# 88frp 联机与 30 账号白名单

启动器的「联机」页支持创建房间、分享房间码、加入房间、复制本地游戏地址和主动断开。支持启动器中的 Microsoft 正版账号和离线账号。全服务最多登记 **30 个固定账号**，不是每个房间最多 30 人，也不是前 30 个用户自动注册。

## 架构和权限

```text
房主 Minecraft 局域网端口 ← 房主启动器
                            ↕ HTTPS
                         88frp TCP 隧道
                            ↕
                    HTTPS 反向代理（证书）
                            ↕ 回环 HTTP
                     nscl-relay 授权网关
                            ↕ 同一个 HTTPS 入口
                         好友启动器 → 127.0.0.1:随机端口 ← 好友 Minecraft
```

88frp 发布的是授权网关的 HTTPS 入口，游戏数据经过授权网关转发；**不要将房主游戏端口直接映射到公网**，否则通过直接游戏地址连接的人不会经过白名单。双方都需要使用启动器接入联机网关。客户端不需要 88frp 账号，也不会得到管理员的 88frp 用户标识、隧道配置或节点凭据。

管理员离线登记账号并发放独立的随机 64 位联机凭证。正版账号绑定 Minecraft UUID；离线账号绑定玩家名生成的离线 UUID。凭证只保存 SHA-256 摘要，服务器依据凭证确定身份，不接受客户端自行声明的用户名作为授权依据。此凭证是独立的邀请授权，不会收集 Microsoft 密码或 Minecraft 登录令牌，也不等同于再次验证 Microsoft 登录；持有凭证的人具有对应账号的联机权限，因此不能公开分享。

白名单上限在网关配置加载和管理员登记时都强制检查。第 31 个账号会被拒绝，文件手动超限或损坏也会拒绝提供服务。没有公开注册、邀请发放或增加名额的 HTTP 接口。白名单每次请求都会重新读取；撤销账号后，原凭证失效，其创建的房间或加入的数据连接也会关闭。客户端离线或崩溃时，房间和连接在约一分钟后失效。

网关不修改游戏的正版认证、白名单或模组要求。原版 LAN 世界能否接受离线玩家取决于游戏或服务端自身的认证设置；拥有启动器联机凭证不保证能进入要求正版认证的游戏世界。

## 构建和登记账号

仅使用调试构建：

```powershell
cargo build --bin nscl-relay
New-Item -ItemType Directory -Force relay-data
target/debug/nscl-relay.exe init relay-data/members.json
target/debug/nscl-relay.exe add-offline relay-data/members.json Alice
target/debug/nscl-relay.exe add-microsoft relay-data/members.json 12345678-1234-1234-1234-123456789abc OnlinePlayer
target/debug/nscl-relay.exe list relay-data/members.json
```

`add-*` 成功后只显示一次联机凭证，私下交付给对应玩家。示例中的正版 UUID 必须换成玩家真实的 Minecraft UUID，可在启动器账号信息中核对。离线玩家修改名称后会变成另一个账号，需重新登记。丢失凭证时先撤销原账号再重新登记；用户自己不能获取或重置凭证。

撤销权限：

```powershell
target/debug/nscl-relay.exe remove relay-data/members.json UUID
```

撤销后释放一个白名单名额。管理员操作通过本地文件锁串行执行；异常终止遗留 `.lock` 文件时，确认没有其他管理员命令运行后再手动移除。白名单文件应只允许网关运行用户和管理员访问，勿放在 Web 静态文件目录。

## 发布 HTTPS 与 88frp

1. 启动网关：`target/debug/nscl-relay.exe serve relay-data/members.json 127.0.0.1:17630`。Linux 使用对应的无 `.exe` 可执行文件。网关只允许监听回环地址。
2. 准备自己的域名和受客户端信任的域名证书。将 [nginx 示例](relay/nginx.example.conf) 中的域名及证书路径替换后，代理到 `127.0.0.1:17630`。示例的 HTTPS 入口在 `127.0.0.1:18443`，需与 frpc 在同一主机或网络命名空间中。
3. 登录 [88frp](https://88frp.com/)，创建一条 TCP 隧道，将本地地址设置为 `127.0.0.1`、本地端口设置为 `18443`，复制平台生成的 FRPC 配置。[88frp FRPC 配置指南](https://88frp.com/client/help-support/FRPC%20%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97) 需要登录。
4. 使用 88frp 平台提供或推荐的 frpc，保留平台生成的节点地址、节点端口、`user`、代理名称和分配的远程端口。对照 [配置结构示例](relay/frpc.88frp.example.toml)，只将目标本地端口改到 HTTPS 入口，保存为 `relay-data/frpc.toml`，运行 `frpc -c relay-data/frpc.toml`。
5. 将自己的域名解析到该 88frp 节点的公网地址。向玩家提供 `https://你的域名:88frp分配的远程端口`，不要提供明文 HTTP 地址或直接使用与证书不匹配的节点 IP。
6. 由操作系统服务管理器管理网关、nginx 与 frpc 的运行、重启和日志。管理员应限制反向代理的请求体、读取超时与请求速率；不记录 Authorization 头，不向外发布 `members.json`。

本网关无需云主机拥有额外的入站公网端口，但需要一台能够持续运行网关、HTTPS 反向代理和 frpc 的主机，以及有效域名和证书。实际节点、可用端口、流量和使用条件以 88frp 账号套餐及平台文档为准。示例不会自动注册、购买套餐、创建隧道或修改平台账号。

## 玩家操作

1. 在启动器账号页选择管理员登记的正版或离线账号。
2. 打开「联机」，填写管理员提供的 HTTPS 服务地址和该账号的联机凭证。可保存服务地址；凭证只在本次启动器运行期间保留，不写入设置文件、日志或整合包。
3. 房主先启动游戏、进入世界并「对局域网开放」，将游戏显示的端口填入启动器，点击「创建联机房间」，复制房间码分享给白名单好友。
4. 好友使用同一网关地址、自己的凭证和房间码点击「加入联机房间」，复制显示的 `127.0.0.1:端口`，在 Minecraft 多人游戏中直接连接。
5. 房主和好友保持启动器开启，游戏版本、加载器和模组应兼容。切换启动器账号会停止当前联机并清除已输入凭证；主动点击「断开联机」或退出启动器也会关闭联机。

## 验证与边界

自动测试覆盖 30 账号上限、重复身份、离线 UUID 绑定、正版/离线凭证、越权操作、撤销后断连、损坏名单拒绝、HTTPS 地址约束、二进制数据顺序与确认、缓冲区和连接上限，以及房主和加入者通过真实 TCP 套接字双向转发数据。界面测试覆盖联机入口、最小窗口和切换账号清除凭证。

当前采用 HTTPS 分块中继：每块最多 64 KiB、每方向每连接最多缓存 512 KiB、全局最多 120 条数据连接、每账号最多 6 条加入连接。Minecraft 的服务器列表探测也会短暂占用数据连接，所以界面的数据连接数不等于玩家人数。每账号最多创建一个房间，网关重启会结束全部房间。不是公网游戏服务器列表，也不提供自动重连或跨版本模组同步。

尚未部署真实网关、填写真实白名单或使用账号完成 88frp 公网验收；本地 TCP 测试不代表实际 88frp 带宽、延迟或 30 人同时游戏的性能保证。
