# 实例备份、恢复与克隆

在「开始 → 管理实例 → 选择实例 → 概览」打开「备份与复制」。备份、恢复和复制在后台执行，游戏运行时锁定这些修改操作。

## 创建备份

- 「备份实例」保存模组、配置、脚本、资源包、光影、存档、截图、游戏设置、服务器列表、资源启停状态和内容安装记录，并记录该实例的 Java、内存等配置。
- 「备份存档」只保存 `saves/`，恢复时不会替换模组、设置或实例配置。
- 窗口显示实际游戏目录、备份范围、距今时间、大小和已保留数量。共享模式和沿用外部版本目录时，会提示该目录也供其他实例使用。
- 默认保存在启动器设置文件旁的 `backups/`；可填写另一完整目录并点击「保存位置并刷新」。保存位置不能位于本次备份的内容目录内。备份在本地保存，未上传到网络。

实例备份包含：`mods/`、`config/`、`defaultconfigs/`、`kubejs/`、`scripts/`、`resourcepacks/`、`shaderpacks/`、`resources/`、`patchouli_books/`、`global_packs/`、`saves/`、`screenshots/`、`options.txt`、`optionsof.txt`、`optionsshaders.txt`、`servers.dat`、`servers.dat_old`、`icon.png`、`pack.png`、`.nscl-content.json` 和 `.nscl/disabled/`；同时覆盖整合包安装记录涉及的自定义根目录。升级恢复点也覆盖新版本新增的根目录，回退时可以移除新增内容。未登记的其他自定义目录请另行保存。

备份不是 `.mrpack`：没有整合包导出的 512 MiB 单文件和 4 GiB 总量限制，文件流式复制并逐项计算 SHA-256。目录层级最多 64 层、文件和目录总数最多 200000。拒绝符号链接、Windows 目录联接、特殊文件和不安全路径。

## 恢复备份

选择「恢复此备份」，阅读范围说明后点击「确认恢复」。启动器会：

1. 核对实例、隔离模式和实际目录，拒绝跨实例或跨目录恢复。完整实例备份允许回退游戏版本，要求该旧版本仍安装在共享游戏目录；仅存档备份仍要求版本相同。
2. 复制并校验全部备份内容，损坏备份不会进入替换阶段。
3. 将当前范围内的数据另存为标记「恢复前」的恢复点。
4. 替换该范围内的内容；备份中没有的同范围文件也会移除。恢复前的数据仍保留在恢复点中。

替换失败时回退已经替换的内容。若文件占用等原因导致回退无法全部完成，错误会给出保留原文件的工作目录，切勿删除该目录。准备阶段可取消；开始替换后会完成提交或回退，避免停留在半恢复状态。

共享模式恢复 `saves/`、模组或配置会影响所有使用同一实际目录的实例。请关闭其他启动器启动的游戏后再操作；NSCL 只能直接跟踪由自己启动的游戏。

备份和恢复点不会自动删除。可通过「打开备份目录」管理旧备份；保留完整的 `snapshot-*` 文件夹，里面的 `snapshot.json` 和 `data/` 必须一起保存。无效或无法读取清单的备份不在列表中显示。建议另外复制重要备份到其他磁盘。

## 克隆实例

在同一窗口填写新名称，可选择是否复制存档、截图和服务器列表，再点击「开始复制」。模组、配置、资源等仍按上述范围复制。

克隆始终创建新的独立实例目录，继承游戏版本、Java 和内存设置，复用共享的游戏本体和依赖；不改动源实例，复制后的存档、模组和配置互不影响。默认包含存档和服务器列表，不包含截图。

## 模组变更前的恢复点

在实例模组的安装、更新或批量卸载确认方案中，可勾选「变更前创建实例恢复点」。勾选后先创建完整的实例内容备份，再执行变更；备份失败或取消会阻止本次变更。整合包整体升级必定先创建恢复点，可在同一窗口回退到历史版本。

## 开发验证

调试模式回归覆盖完整恢复、恢复前恢复点、共享目录的仅存档恢复、克隆选项与独立性、损坏校验、目录穿越、复制取消清理、发布中途失败回退，以及后台服务的游戏运行锁定。
