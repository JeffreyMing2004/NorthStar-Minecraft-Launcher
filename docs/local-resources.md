# 实例资源管理

在「开始 → 管理实例」选择实例，右侧分别进入「模组」「资源包」「光影」。列表显示本地名称、版本、文件名、大小及启用状态，支持搜索、刷新和打开实际目录。

## 导入、禁用与移除

- Windows 可点击「导入文件」选择一个或多个 JAR / ZIP，也可将本地文件拖到对应资源标签页。每次最多导入 32 个文件，单个文件不超过 512 MiB；源文件保留，同名文件不覆盖。资源包 ZIP 需要根目录的 `pack.mcmeta`，光影 ZIP 需要 `shaders/` 目录；不把资源 ZIP 当作整合包安装。
- 点击行内「禁用」或「启用」切换可用状态。模组使用 `.jar.disabled` 后缀；资源包、光影移到实际游戏目录的 `.nscl/disabled/<类别>/`，因此已有的目录形式资源包也能禁用。启用时如存在同名资源，会拒绝覆盖。
- 点击「移除」并确认后，文件或文件夹保留在实际游戏目录的 `.nscl/trash/<类别>/`。可通过「打开回收目录」找到原文件，再复制回对应目录；不会直接永久删除这些资源。
- 已登记模组仍支持在线检查更新、安装依赖及批量卸载。批量卸载的 JAR 同样保留在本地回收目录。

资源包与光影的「启用」表示恢复到游戏可读取的目录。资源包选择、排序及光影设置继续在游戏内操作；光影需要游戏内相应的光影支持。

## 模组记录与依赖

整合包自带、手动添加和通过 NSCL 单独安装的模组出现在同一列表。Fabric JAR 可从本地元数据读取名称和版本，其他文件使用本地文件名。

已登记模组的禁用状态保存在安装记录的文件路径中。更新会保留其禁用状态；启用、禁用或移除已登记模组前，会检查已登记的必需依赖和冲突。已禁用的模组不再计入活动依赖图；安装需要某个已禁用依赖的模组时，会提示先启用该依赖。

已登记模组的文件丢失或内容改变时，列表会显示对应状态。丢失文件的安装记录仍可移除，移除前同样检查依赖；内容改变的文件会要求先刷新或核对，不直接覆盖。

本地 JAR 没有在线项目记录时，仍可启用、禁用和移除，但不能据此自动确认全部依赖或在线更新。整合包清单中已知文件的路径会随禁用、恢复调整，避免把有意禁用误报为丢失。

## 目录与操作范围

所有操作沿用实例的实际游戏目录：独立实例、共享目录和已有版本目录均适用。游戏运行或已有后台任务时禁止修改资源。列表读取、元数据解析、复制和状态修改在后台完成，列表按需绘制并缓存，最多显示 1000 项。

操作前重新确认实例版本、隔离模式、目录和文件状态；过期列表、符号链接、目录穿越、修改过的已登记 JAR 或目标文件冲突会给出错误并保留原文件。文件导入按批次暂存，失败或取消时不发布半套文件。

交互参考 [Axolotl Launcher](https://axlmc.org/) 的实例内容分类和列表管理；NSCL 自行实现，项目致谢保留在「更多 → 关于」。
