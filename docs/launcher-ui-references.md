# 启动器界面参考与本次改进

参考日期：2026-10-26。仅参考公开的界面与交互思路，以下改进由 NSCL 自行实现。

| 参考项目 | 观察到的设计 | NSCL 的现状与可采用方向 |
| --- | --- | --- |
| [HMCL](https://hmcl.huangyuhui.net/) | 游戏安装页将 Minecraft、加载器及附加组件分组，并显示互斥关系 | 已有分步安装与加载器兼容筛选；后续可增加安装确认页中的组件摘要和兼容性说明 |
| [PCL](https://github.com/Meloong-Git/PCL/blob/main/Plain%20Craft%20Launcher%202/Pages/PageInstance/PageInstanceLeft.xaml) | 实例管理区分概览、设置和 Mod 管理，提供常用目录快捷方式 | 实例管理改为独立页面，提供搜索分类、概览与文件页，接入已有实例配置、模组管理、归档恢复等操作 |
| [Axolotl Launcher](https://axlmc.org/) | 按实例集中管理内容，资源设置提供不同连接与下载来源选项，并提供备份入口 | 已有实例、模组管理及多游戏目录；下载来源在后台自动切换，手动选项集中在设置页；后续可增加存档备份与恢复入口 |

本次保留 NSCL 当前的深色配色、顶部导航和卡片布局，优先改进失败后如何继续操作，而不是更换整套视觉风格。关于页新增三个项目的名称与仓库链接，标明设计参考与致谢。

实例管理同时参考 [HMCL 的实例详情页](https://github.com/HMCL-dev/HMCL/blob/main/HMCL/src/main/java/org/jackhuang/hmcl/ui/instances/GameInstancePage.java) 对配置与内容功能的分组。NSCL 左侧浏览不会直接改变启动实例；右侧集中显示概览、实例设置、模组管理和目录入口。归档列表只在进入该分类或手动刷新时读取，普通绘制使用已加载的实例与版本信息。

参考 Axolotl 的实例内容分类，NSCL 增加模组、资源包、光影的本地管理列表。已登记与手动添加的文件统一展示，提供导入、启用/禁用及保留回收副本的移除操作；模组保留原有在线更新和依赖检查。实现未复用参考项目的代码或素材，关于页保留项目致谢。

版本管理使用窄列表和分类下拉框，读取实例或已有版本目录中的本地图标；没有图片时显示对应类型图标。启动按钮固定在详情区右下角。窗口、任务栏、Alt+Tab 及 Windows 可执行文件使用 NSCL 自有标志。

## 下载与网络恢复

- Minecraft 下载页由后台自动选择下载源，依次尝试 **BMCLAPI（bangbang93）→ minguncle → 官方源**，连接失败或校验不通过时切换到下一来源。下载页仅保留版本搜索、筛选和刷新，不显示下载源、代理方式或网络设置入口；需要手动指定来源或连接方式时可进入设置页。
- 刷新版本列表时保留已有结果，失败后仍可浏览已有列表；首次加载失败可重新加载。
- 默认继续跟随系统代理。选择直连后，游戏下载、加载器与 Modrinth 请求不使用代理，不修改 Windows 代理配置，也不静默回退到直连。
- 网络弹窗显示简短原因与操作建议，原始错误保存在可展开的「技术详情」中，并可完整复制。版本列表加载失败提供重试；代理相关失败提供显式的「切换直连并重试」。安装、导入等修改文件的操作不会从弹窗中自动重跑。
- `10013` 是 [Windows Winsock 的访问被拒绝错误](https://learn.microsoft.com/en-us/windows/win32/winsock/windows-sockets-error-codes-2)，不表示 Mojang 返回了 HTTP 错误。代理不可用和受限调试环境都需要单独排查；更换镜像不能保证解决本地连接权限问题。

## 仅使用调试模式验证

当前开发只构建和运行调试版：

```powershell
cargo build --locked --bin nscl
.\target\debug\nscl.exe
```

需要普通桌面进程权限与网络访问；从隔离或受限执行环境启动的程序可能继承其限制。

自动测试覆盖系统代理与直连的请求路径、旧配置迁移、网络错误分类、失败后的恢复按钮以及最小窗口布局。需要联网诊断时显式运行：

```powershell
cargo test --lib live_mojang_version_manifest -- --ignored --nocapture
```

该测试分别报告系统代理和直连访问官方版本列表的结果，不修改任何系统网络设置。

本次用同一份调试测试程序复测：普通桌面进程下，系统代理和直连均成功读取 920 个版本；受限执行环境中，系统代理路径复现截图中的 `10013`，直连路径返回 DNS `11001`。因此该现场需要纠正调试程序的启动环境，切换下载源或连接方式不能解除进程继承的网络限制。
